The framework to use on every design question

  1. Clarify (5–8 min). Scale, read/write ratio, consistency needs, in-scope vs out-of-scope. Never start with classes.
  2. Requirements. Functional list, then non-functional: concurrency, latency, durability, extensibility.
  3. Entities & relationships. Nouns to classes, identify value objects and the aggregate root.
  4. API contract. Endpoints, request/response, status codes, idempotency.
  5. DB schema. Tables, keys, indexes, and one sentence on why each index exists.
  6. Class design. Interfaces first, then the pattern that earns its place. Say the pattern name.
  7. Edge cases, concurrency and failure. This is where the interview is actually won or lost.
  • Answer out loud, and for anything tagged CODE IT, actually write compilable Java against a timer.
  • Open key points only after attempting the answer.
  • Whenever you say a design word (idempotent, optimistic lock, saga), be ready for the immediate follow-up: "show me the table and the code path."
  • Days 3 and 5 carry the most weight for a Java backend role. Do not skip them to finish Day 4.
